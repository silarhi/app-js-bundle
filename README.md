<h1 align="center">App JS Bundle</h1>

<p align="center">
    <strong>The PHP companion to <a href="https://github.com/silarhi/app-js">@silarhi/app-js</a> for Symfony.</strong><br>
    <code>load_page()</code>, PHP enums as TypeScript modules, and form shapes that check <code>formView()</code> paths when compiling.
</p>

---

## Features

- `load_page()`, the Twig function behind the `data-page` listener;
- `app-js:dump-enums`, the PHP enums marked `#[EnumToJs]` as TypeScript or JavaScript modules;
- `app-js:dump-forms`, the shape of the form types marked `#[FormToJs]`, for `formView<Shape>()` to check form paths
  when compiling.

## Install

```bash
composer require silarhi/app-js-bundle
```

```php
// config/bundles.php
return [
    // ...
    Silarhi\AppJsBundle\SilarhiAppJsBundle::class => ['all' => true],
];
```

## Pages

```twig
<div {{ load_page('party', {id: party.id}) }}></div>
<div {{ load_page(['party', 'address']) }}></div>
```

renders the `data-page` and `data-page-params` attributes that `@silarhi/app-js` reads to load the page modules.

## Enums

```php
use Silarhi\AppJsBundle\Attribute\EnumToJs;

#[EnumToJs]
enum LeaseStatus: string
{
    case Draft = 'draft';
    case Active = 'active';
}
```

```bash
bin/console app-js:dump-enums
```

writes `assets/js/enums/LeaseStatus.ts`:

```ts
export const DRAFT_NAME = 'Draft'
export const ACTIVE_NAME = 'Active'

const LeaseStatus = Object.freeze({
    Draft: 'draft',
    Active: 'active',
})
export default LeaseStatus
```

Only the enums marked `#[EnumToJs]` are dumped (`#[EnumToJs(name: 'Status')]` renames the module). Unit enums take
their case names as values.

On Symfony 7.3+, the bundle finds them through autoconfiguration, wherever they live: an enum must be loaded by a
service resource of the application, as the default `App\` resource of `config/services.yaml` loads `src/`, and not
sit under one of its `exclude` paths. Symfony 6.4 to 7.2 registers no enum in the container: list their directories in
`enums.paths` instead (see [Configuration](#configuration)).

## Form shapes

```php
use Silarhi\AppJsBundle\Attribute\FormToJs;

#[FormToJs]
final class PartyType extends AbstractType
{
    // name, address (an AddressType), phones (a collection of PhoneType)
}
```

```bash
bin/console app-js:dump-forms
```

writes `assets/js/forms/PartyForm.ts`:

```ts
// Generated by app-js:dump-forms from App\Form\PartyType, do not edit
import type { FormCollection, FormField } from '@silarhi/app-js/form'

export interface PartyForm {
    name: FormField<HTMLInputElement, string>
    country: FormField<HTMLSelectElement, string | null>
    tags: FormField<HTMLElement, string[]>
    address: {
        street: FormField<HTMLInputElement, string>
        city: FormField<HTMLInputElement, string>
    }
    phones: FormCollection<{
        number: FormField<HTMLInputElement, string>
    }>
}
```

and the page checks its paths when compiling:

```ts
import type { PartyForm } from '@/js/forms/PartyForm'

const form = formView<PartyForm>(container.querySelector('form'))
form.get('phones.0.number')
form.get('adress.city') // TS2345
form.get('country').element // HTMLSelectElement | null
form.field('tags').value // string[]
```

The shape is read from the form view, as `formView()` reads the DOM: embedded forms are nested objects, collections
take the shape of their prototype and rendered items, expanded choices are one field. The CSRF token is left out.

A field names the element it is rendered as and the value `field().value` reads, from the core type it extends:

1. a choice (an entity, an enum, a country) is an `HTMLSelectElement` read as `string | null`, or `string[]` when
   multiple; expanded, the container of its options read as `string`, or `string[]` when multiple;
2. a checkbox is read as a `boolean`, a radio as `string | undefined` (the checked value of its group);
3. a textarea and the other core types rendered as an input are read as a `string`; a button has no value.

A type no core type tells about, or a field two variants render differently, is a plain `FormField`: an `HTMLElement`
read as any value. A form type of your own whose widget renders something else than its parent, or a field whose
behavior (`bindField()`) reads another value, should extend a type that renders and reads the same.

An embedded form whose type is marked `#[FormToJs]` too is a reference to its interface, imported from its file:

```ts
import type { FormCollection, FormField } from '@silarhi/app-js/form'
import type { AddressForm } from './AddressForm'
import type { PhoneForm } from './PhoneForm'

export interface PartyForm {
    name: FormField
    address: AddressForm
    phones: FormCollection<PhoneForm>
}
```

Only when the shapes are the same: an embedded form built with options that change its fields
(`->add('billingAddress', AddressType::class, ['with_country' => true])`) keeps its own shape, written out.

### Fields that are not always rendered

A form whose fields depend on its options or its data is built once per **variant**. A field missing from a variant
becomes optional (`siren?: FormField`), so the page reads it with `form.find()`.

Variants known at compile time are an array of `options` (and scalar `data`):

```php
#[FormToJs(variants: [
    'company' => ['options' => ['with_siren' => true]],
    'person' => ['options' => ['with_siren' => false]],
])]
final class PartyType extends AbstractType
```

Variants that need objects or services come from a provider, a service by its class:

```php
#[FormToJs(variants: LeaseFormVariants::class)]
final class LeaseType extends AbstractType

final class LeaseFormVariants implements FormVariantProviderInterface
{
    public function getVariants(): iterable
    {
        yield 'furnished' => new FormVariant(data: (new Lease())->setFurnished(true));
        yield 'unfurnished' => new FormVariant(['issuer' => new Issuer()], new Lease());
    }
}
```

Build the data in memory: the dump must give the same files on every machine, never read it from a database.

Fields added by a `PRE_SET_DATA` listener only appear with data. `app-js:dump-forms` warns about each form type with
such a listener and no variant with data; `#[FormToJs(dynamic: false)]` silences it for listeners that add no field.

Other options: `#[FormToJs(name: 'Party')]` names the interface and its file (`PartyForm` for `PartyType` by default).

## Configuration

```yaml
# config/packages/silarhi_app_js.yaml
silarhi_app_js:
    enums:
        output_dir: '%kernel.project_dir%/assets/js/enums' # owned by app-js:dump-enums: its other .ts files are removed
        format: ts # or js
        # Symfony 6.4 to 7.2 only: the directories scanned for #[EnumToJs] enums, with their namespace prefix
        paths:
            '%kernel.project_dir%/src/Enum': 'App\Enum'
    forms:
        output_dir: '%kernel.project_dir%/assets/js/forms' # owned by app-js:dump-forms
        format: ts # or js
```

### JavaScript

With `format: js`, the enums are `.js` modules (the same code), and the form shapes `.d.ts` declarations: a shape is a
type only. A JavaScript page reads it through JSDoc, and `checkJs` checks the paths:

```js
/** @type {import('@silarhi/app-js/form').FormView<import('@/js/forms/PartyForm').PartyForm>} */
const form = formView(container.querySelector('form'))
```

## Continuous integration

Commit the dumped files and check they are up to date:

```bash
bin/console app-js:dump-enums --check
bin/console app-js:dump-forms --check --strict
```

`--check` fails when a file would change, without writing it; `--strict` fails on the warnings.
